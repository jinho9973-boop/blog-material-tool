# 네이버 블로그·SNS 콘텐츠 자동 정리

AI API를 호출하지 않고, 사람이 준비한 `blog1.json`, `blog2.json`을 블로그 글,
이미지와 채널별 원고로 조립하는 Linux용 도구입니다. YouTube Data API v3는 인기
이슈를 가져올 때만 사용합니다. 자동 업로드와 실제 동영상 렌더링은 하지 않습니다.

## 구조와 기술

```text
content_tool/
  youtube.py      YouTube 조회, 정렬, 정치 필터, 유사 주제 통합
  material.py     재료 JSON 검증
  writers.py      블로그·Threads·X·Instagram·Clip 원고
  images.py       Pillow 이미지 합성, 한글 자동 줄바꿈
  pipeline.py     공통 실행 흐름
  novel.py        장편 소설 원고 → 장면 이미지·AI 프롬프트·자막·MP4 영상 변환
fonts/            나눔고딕과 OFL 라이선스
examples/         블로그 재료 예시
novels/wall_3pm/  장편 소설 《벽 너머, 오후 세 시》 설정집 및 1~5화 원고·장면 콘티
tests/            단위·통합 테스트
run.py            명령줄 프로그램
web_app.py        로컬 웹 미리보기 및 소설 영상 제작 도구
```

- Python 3.10 이상
- `requests`: YouTube Data API v3
- `Pillow`: PNG 합성
- `Flask`: 마지막 단계의 로컬 웹페이지
- `python-dotenv`: `.env` 읽기

문장과 이미지 문구는 재료 파일에서만 가져옵니다. 생성형 AI API는 사용하지 않습니다.

## 설치

```bash
git clone <저장소 주소>
cd blog-material-tool
python -m pip install -r requirements.txt
cp .env.example .env
```

`.env`에 YouTube Data API v3 키를 넣습니다. `.env`는 Git에 올라가지 않습니다.

```dotenv
YOUTUBE_API_KEY=발급받은_키
```

## 명령어

유튜브 인기 이슈를 수집합니다.

```bash
python run.py --youtube --out 오늘폴더
```

기본 검색어는 **공란**입니다. 따라서 사회·사건·날씨·연예·국제·경제 등 주제를
가리지 않고 최근 이슈를 모두 후보로 가져옵니다. 기본 출처는
`KBS News, SBS 뉴스, MBCNEWS, JTBC News, 연합뉴스TV`입니다. 첫 실행에서는 채널명을
YouTube에서 검색해 **이름이 정확히 같은 채널**의 ID를 `channels.json`에 저장합니다.
다음 실행부터는 저장한 ID를 사용합니다. 각 채널의 uploads 재생목록에서 최근 하루
영상을 가져옵니다. 정치 제외 키워드가 든 영상은 주제와 관계없이 계속 제외합니다.

하루 평균 조회수로 정렬하고, 정치 키워드가 든 영상은 제외합니다. 제목 토큰의
Jaccard 유사도 또는 공통 핵심어 수로 비슷한 주제를 하나로 묶습니다. 좋아요 수가
비공개인 영상은 JSON에서 `null`, 표에서 `-`로 나옵니다.

```bash
python run.py --youtube --keywords 경제,연금,부동산 --out 오늘폴더
```

`--keywords`는 경제처럼 특정 주제만 보고 싶을 때 선택해서 사용합니다. 옵션을
생략하면 아무 키워드로도 거르지 않습니다.

기본은 최근 하루입니다. 영상이 적은 날에만 기간을 늘릴 수 있습니다.

```bash
python run.py --youtube --days 7 --out 오늘폴더
```

출처 채널도 명령줄에서 바꿀 수 있습니다.

```bash
python run.py --youtube --source-channels "KBS News,SBS 뉴스" --out 오늘폴더
```

API 키가 없는 컴퓨터에서는 함께 들어 있는 가짜 영상 자료로 전체 흐름을 시험합니다.
정치 영상 제외, 비슷한 주제 묶기, 순위 계산과 두 결과 파일 저장이 모두 실행됩니다.

```bash
python run.py --유튜브 --유튜브예시 sample_youtube.json --저장폴더 오늘폴더
```

블로그와 채널별 결과를 만듭니다.

```bash
python run.py --material 오늘폴더 --blogs 1,2 \
  --channels threads,x,instagram,clip --out 오늘폴더/결과
```

이미지만 다시 만듭니다. `--out`을 생략하면 `오늘폴더/결과`를 씁니다.

```bash
python run.py --compose 오늘폴더
```

모든 명령은 표준 출력에 아래 형태의 JSON을 출력하고, 전체 성공 시 종료 코드 `0`,
실패 시 `1`을 반환합니다. 한 블로그가 실패해도 다른 블로그는 계속 처리합니다.

```json
{
  "성공": true,
  "파일목록": ["오늘폴더/결과/blog1/본문.md"],
  "블로그결과": [
    {"블로그": 1, "성공": true, "파일목록": ["오늘폴더/결과/blog1/본문.md"]}
  ]
}
```

같은 명령을 한글로도 쓸 수 있습니다.

```bash
python run.py --유튜브 --기간 1 --저장폴더 오늘폴더
python run.py --재료 오늘폴더 --블로그 1,2 --저장폴더 오늘폴더/결과
python run.py --그림다시 오늘폴더
```

## 재료 파일

`오늘폴더/blog1.json`, `오늘폴더/blog2.json`을 각각 둡니다. 두 블로그의 내용은
섞이지 않습니다.

```json
{
  "주제": "국민연금 조기수령",
  "방향": "숫자로 보는 현황",
  "검색어": ["국민연금 조기수령 감액"],
  "훅": "106만명이 당겨 받는데 실제로 어떤 점을 봐야 할까?",
  "핵심": [
    "조기수령자는 신청 시점에 따라 받는 금액이 달라집니다.",
    "당장 필요한 생활비와 앞으로 받을 기간을 함께 봐야 합니다.",
    "신청 전에는 공식 기관의 최신 안내를 확인해야 합니다."
  ],
  "숫자": [
    {
      "항목": "조기수령자",
      "값": "106만9,034명",
      "출처": "국민연금공단 2026.7"
    }
  ],
  "소제목": ["조기수령이란", "왜 먼저 받을까", "확인할 부분", "신청 전에 할 일"],
  "소제목별_내용": [
    ["정해진 나이보다 앞서 연금을 받는 방법입니다.", "신청 시점에 따라 받는 금액이 달라집니다."],
    ["은퇴 뒤 소득이 비는 기간을 채우려는 경우가 있습니다.", "생활비가 급한 상황도 고려됩니다."],
    ["지금 필요한 돈만 보고 결정하면 안 됩니다.", "앞으로 받을 기간도 살펴야 합니다."],
    ["공식 기관의 최신 안내를 확인합니다.", "예상 수령액도 공식 채널에서 조회합니다."]
  ],
  "출처링크": ["https://www.nps.or.kr/"],
  "태그": ["국민연금", "조기수령", "연금정보"]
}
```

검증 규칙:

- `핵심`은 3~5개, `소제목`은 4~6개여야 합니다.
- `소제목`과 `소제목별_내용`의 개수가 같아야 합니다.
- 출처는 `http` 또는 `https` 주소여야 합니다.
- 값이 없거나 형식이 잘못되면 사실이나 숫자를 보충하지 않고 해당 블로그를 실패로
  표시합니다.

서로 다른 주제의 전체 예시는 [`examples/blog1.json`](examples/blog1.json)과
[`examples/blog2.json`](examples/blog2.json)에 있습니다.

## 배경 이미지

재료 폴더 아래 `bg/`에 다음 이름으로 넣습니다.

```text
bg_blog1_thumb.png
bg_blog1_card1.png
bg_blog1_card2.png
bg_blog1_insta1.png ... bg_blog1_insta6.png
```

블로그 2는 `blog1`을 `blog2`로 바꿉니다. 파일이 없으면 남색 단색 배경을
자동으로 사용합니다. `prompts.txt`에는 Grok Bot이 배경을 만들 때 쓸 영문 프롬프트가
들어갑니다. 배경에는 글자·숫자·로고를 넣지 않도록 명시되어 있습니다.

출력 이미지:

- 썸네일: 1080×1080
- 요약 카드: 1080×1080, 1~2장
- Instagram 카드뉴스: 1080×1350, 4~6장

## 결과 폴더

```text
결과/blog1/
  본문.md
  본문.txt
  제목후보.txt
  태그.txt
  prompts.txt
  썸네일.png
  요약카드1.png
  threads/본문.txt, 답글.txt
  x/게시물.txt
  instagram/캡션.txt, 카드뉴스1.png ...
  clip/대본.txt, 자막.txt, 제목.txt, 태그.txt, 영상프롬프트.txt
```

`blog2/`도 같은 구조입니다. Clip 결과는 15~30초 분량으로 쓸 짧은 대본·자막과
영문 영상 프롬프트입니다.

## 장편 소설 → 장면 이미지 → MP4 영상 전환

`novels/wall_3pm/`에 장편 소설 **《벽 너머, 오후 세 시》** 설정집(`series_bible.json`, `설정집_및_장편플롯.md`)과 초반 1~5화 원고(`ep01.json` ~ `ep05.json`)가 들어 있습니다. 회차별로 소설 원고, 캐릭터 외형이 고정된 AI 이미지 생성 프롬프트, 이미지→영상(I2V) 모션 프롬프트, SRT 자막, 장면 PNG 카드, 카메라 무빙(`zoom`/`pan`·페이드)이 적용된 `영상.mp4`까지 한 번에 생성합니다 (`ffmpeg` 필요).

```bash
# 특정 회차(예: 3화) 이미지 + MP4 세로 영상(9:16) 생성
python run.py --소설 novels/wall_3pm --회차 3 --비율 9:16 --저장폴더 결과/소설영상

# 1~5화 전체 변환 (16:9 가로형)
python run.py --소설 novels/wall_3pm --비율 16:9 --저장폴더 결과/소설영상
```

- **새 회차 집필**: `novels/wall_3pm/ep06.md`처럼 일반 마크다운/텍스트로 본문만 적어도 문단을 분석해 자동으로 장면 분할·프롬프트·장면 이미지·MP4 영상을 만듭니다. 웹페이지의 `새 회차 소설 원고 직접 쓰고 바로 변환하기` 칸에서도 바로 작성할 수 있습니다.
- **외부 AI 이미지·영상 결합**:
  - `이미지_프롬프트.txt`로 생성한 이미지를 `novels/wall_3pm/bg/ep03_scene_02.png` 형태로 넣으면 자막과 비네팅을 입혀 합성합니다.
  - `영상전환_프롬프트.txt`로 만든 AI I2V 클립을 `novels/wall_3pm/clips/ep03_scene_02.mp4`에 넣거나 `novels/wall_3pm/bgm.mp3`를 두면 최종 `영상.mp4` 렌더링에 자동 반영됩니다.

## 로컬 웹페이지

먼저 명령줄 기능을 확인한 뒤 다음 명령으로 실행합니다.

```bash
python web_app.py
```

브라우저에서 <http://127.0.0.1:5000>을 엽니다. YouTube 수집, 전체 결과 생성,
이미지 재생성 버튼과 본문 미리보기·복사, PNG 미리보기·다운로드를 제공합니다.
API 키 없이 시험하려면 `예시 데이터로 연습하기` 버튼을 누릅니다.
외부에 공개하는 서버가 아니라 같은 컴퓨터에서 쓰는 로컬 도구입니다.

## 테스트

```bash
python -m pip install pytest
python -m pytest -q
```

YouTube API 자체 호출은 키와 일일 할당량이 필요합니다. 테스트는 고정된 모의 API
응답으로 정렬, 정치 제외, 유사 주제 통합과 파일 출력을 확인합니다.

## 운영 시 보완 권장 사항

- YouTube `search.list`는 호출당 할당량 비용이 큽니다. 채널 ID를 찾는 첫 실행 후
  `channels.json`을 유지하면 uploads 재생목록만 조회하므로 비용이 크게 줄어듭니다.
- 정치 제외어와 유사도 기준은 규칙 기반이므로 `POLITICS_TERMS`, `STOPWORDS`를 실제
  오탐 사례에 맞춰 관리해야 합니다.
- 재료를 넣기 전에 출처의 발행일과 원문을 사람이 확인해야 합니다. 이 도구는 출처
  내용을 검증하거나 최신 사실을 추론하지 않습니다.
- 공개 웹서버로 바꾸려면 로그인, 작업별 저장 공간, 업로드 크기 제한과 경로 접근
  통제를 별도로 추가해야 합니다.
